# Live screenshots

The README images are captured directly from the [deployed app](https://octopusgarage.github.io/mbti-lab/) in Chromium. They preserve the app's UI; no replacement copy, CSS, result payload, or device frame is injected.

| File | Capture |
| --- | --- |
| `images/home.png` | English home page at 1440 × 820 |
| `images/assessment.png` | Question 7 of a short English assessment at 390 × 844 |
| `images/report.png` | English ENFJ report at 390 × 844 |
| `images/types.png` | Chinese type search for `者` at 390 × 844 |
| `images/sharing.png` | English result-sharing dialog at 390 × 844 |
| `images/share-card.png` | Original 1080 × 1080 PNG generated by the live Save image action |

The assessment uses scripted A answers for all 60 questions. The report and share card are real outputs of that demonstration flow, not a personal result. The assessment clock is advanced through answer feedback; page styling and document content are left intact. The capture blocks the analytics script and uses an isolated browser context.

[Capture metadata](images/capture.json) records the timestamp, live application entry asset, browser version, viewport, language, and URLs. These are browser captures at mobile viewport sizes, not photographs of physical devices.

## Refresh

With the Node.js version in `.node-version`:

```sh
npm ci
npx playwright install chromium
npm run docs:screenshots
```

The command visits the production URL, completes the scripted assessment, and replaces the images and metadata. It uses the live deployment rather than a local preview, so deploy app changes before refreshing their screenshots. It does not publish social posts or use personal answers.

Review the images and metadata before committing. Update the capture date in the README if it changes.
